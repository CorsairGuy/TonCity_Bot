# Проверки регрессий

## Общая карта

После установки зависимостей фронта (`npm ci --prefix src/web/client`):

```sh
node scripts/tests/city-world-regressions.cjs
node scripts/tests/city-sections.cjs
npm run build --prefix src/web/client
```

Проверки исполняют реальные обработчики исходников с управляемыми состоянием, API и БД. Они не подключаются к игре и не используют токены. Проверяются отмена отложенного выбора, частичное сохранение и повтор ускорителей, смена состава прогноза, публикация и сохранение секций, устаревшие ответы и ошибки обновления.

Это целевые проверки алгоритмов, а не полная браузерная проверка страницы. Жесты дополнительно проверялись в Chromium на настоящем Canvas с тестовыми городами: pinch с разным порядком отпускания пальцев, touchcancel, обычный тап, совместимые mouse-события, прерывание наезда и смена обработчиков во время жеста. Боевые аккаунты и расход ресурсов не использовались.


## 2048: точное сравнение с исходным WASM

Все проверки локальные, без токенов, БД и запросов к игре. Для тайминга используйте Node 22 и свободное от других вычислений окружение. Нужны исходный бинарник из GitHub и новая сборка; нельзя подменять эталон пересборкой исходников.

```sh
# Исходный бинарник до оптимизации, SHA256:
# 45ba979f37a9b84fa26f34b768b7b9bf2b16dee50cebfc35702c4c4120badcf2
git show 108f5261f64bbc4544d2b34280897df5fd99a044:src/modules/game2048.wasm > /tmp/reference.wasm

# Инструмент WABT нужен только для проверки старого бинарника, вне Docker бота:
npm install --prefix /tmp/2048-tools --no-save --package-lock=false wabt@1.0.39
node scripts/tests/game2048-instrument-reference.cjs /tmp/reference.wasm /tmp/reference-scores.wasm \
  --wabt=/tmp/2048-tools/node_modules/wabt

# SDK 22 нужен только для сборки; обычный бинарник уже лежит в git:
GAME2048_DIAGNOSTICS=1 WASI_SDK_PATH=/absolute/path/to/wasi-sdk-22.0 \
  vendor/game2048/build.sh /tmp/candidate-scores.wasm
node scripts/tests/game2048-exact.cjs \
  --reference /tmp/reference.wasm --candidate src/modules/game2048.wasm \
  --reference-scores /tmp/reference-scores.wasm --candidate-scores /tmp/candidate-scores.wasm \
  --boards 256 --games 2 --repeats 5 --warmup 32 --benchmark-boards 256 \
  --write-corpus /tmp/2048-corpus.json --json /tmp/2048-result.json
```

Observer проверяет SHA эталона, восемь точек захвата и валидность WASM. Он добавляет чтение уже рассчитанных результатов через globals, сохраняя исходные инструкции поиска. Harness сравнивает обычные и проверочные модули, выбранный ход и все 32 бита каждой из четырёх оценок. Полные партии используют одинаковые seed; лимит незавершённой партии считается ошибкой. Есть пустые, плотные и крайние доски, а также позиции с меняющейся последней строкой, вызывавшие коллизии прежнего хеша.

Тайминг использует свежие instances, отдельный прогрев и пары с чередованием порядка старый/новый; проверка оценок и кодирование в него не входят. Сохраняются SHA модулей, Node/архитектура, median/p95/p99/max, общее время и память. Для сравнения вариантов используйте один сохранённый `--corpus ... --games 0`. Результаты конечного корпуса дополняют [обоснование эквивалентности](../../vendor/game2048/README.md), но не заменяют его.

Сохранённый [итоговый отчёт](game2048-result.json) содержит SHA, параметры, результаты партий и сводку замеров; [разбор результата](../../vendor/game2048/README.md#проверка-2026-10-25) — рядом с исходниками.


## 2048: восстановление worker

```sh
node scripts/tests/game2048-worker.cjs
```

На Node 22 проверка исполняет реальный менеджер с управляемыми worker: поздние `message/error/exit`, остановка перед заменой, однократный повтор нескольких запросов, отсутствие повторов завершённых задач, снимок доски, ошибки создания/отправки/вычисления/остановки и предел попыток. Отдельно запускается настоящий постоянный worker на пустой, обычной и терминальной досках; проверяется, что основной поток не загрузил модуль солвера. Запросов к игре и БД нет. Общий watchdog завершает проверку с ошибкой при зависании.

После двух неудачных попыток `bestMove` возвращает ошибку; поиск в основном потоке не выполняется. При неудачном `terminate()` новый worker не создаётся до фактического `exit`, чтобы не накапливать живые потоки. Это не ограничивает максимальную глубину и не меняет сам WASM.


## Карта городов: загрузка сайдбара и стоимость обновлений

```sh
node scripts/tests/city-world-loading.cjs
node scripts/tests/city-map-labels.cjs
node scripts/tests/city-sidebar-data.cjs
node scripts/tests/city-panel-window.cjs
node scripts/tests/city-panel-tabs.cjs
node scripts/tests/city-world-regressions.cjs
node scripts/tests/city-sections.cjs
npm run build --prefix src/web/client
```

Новые проверки исполняют реальные функции/хуки и загрузчики из исходников через TypeScript/esbuild:

- просмотр использует готовые показатели без полного редактора, а черновики, действия и передача режима удерживают его, включая ещё не закоммиченный transition;
- камера обновляет готовые показатели без таймера; наезд по клику и отъезд «Все города» сохраняют назначение, движение не объявляется завершённым раньше времени;
- равные Sets и итоговые подписи сохраняют кэши; выделение не пересчитывает бейджи, validSet меняет геометрию только в режимах затемнения;
- индексы бейджей и цены очереди совпадают с прежними формулами на воспроизводимых данных, дубликатах, приоритетах и больших очередях; проверяется линейное число чтений вместо чувствительных к машине временных порогов;
- загрузочные данные и готовность находятся в одной фоновой операции, встроенный прогресс не будит редактор на каждый ответ, ошибки и устаревшие результаты обрабатываются отдельно от пользовательских изменений.

Просмотр использует общий снимок (постройки/секции обновляются SSE); отдельного перечитывания баланса/планов при каждом посещении города больше нет. Ручное «Обновить» города сохранено. Эти локальные регрессии дополняются браузерным прогоном с реальными React/Primer/Canvas, синтетическими городами и управляемыми ответами — без игровых аккаунтов.

`city-panel-window.cjs` проверяет координаты смешанных строк, полную высоту, абсолютные индексы, закрепление drag/focus и переходы через недоступные действия. `city-panel-tabs.cjs` исполняет настоящие панели, запрашивая поздние строки раньше первых: бюджеты реконструкции/реновации не зависят от порядка отрисовки, удаление и перетаскивание сохраняют исходные ID/индексы, журнал и прогноз сохраняют состав и порядок дней.

Браузерные регрессии (два терминала; нужен локальный Chromium и отдельно установленный Playwright):

```sh
node scripts/tests/browser/city-sidebar-window/server.mjs
# Во втором терминале:
node scripts/tests/browser/city-sidebar-window/run.cjs
```

Если Playwright/Chromium установлены вне проекта, задайте `PLAYWRIGHT_MODULE=/путь/к/playwright-core` и `CHROMIUM_PATH=/путь/к/chromium`. Стенд слушает только `127.0.0.1:5200` (`PORT`, `CITY_FIXTURE_URL` позволяют изменить адрес). Зависимости React/Vite/Primer берутся из `src/web/client/node_modules`; игровые аккаунты, БД и авторизация не используются.

Проверяются 11 видов панелей по 500 записей: ограниченное число DOM-строк, последняя запись, отсутствие перекрытий, исходные ID удаления, Tab/Shift+Tab, пропуск недоступных ускорителей, сохранение drag-строки при прокрутке и перенос 0→499. Отдельный случай — 36 вложенных групп по 50 действий: последняя запись 1799 и переходы между группами. Тест ждёт реальной готовности скроллера, поэтому ловит преждевременное подключение окна до `OverlayScrollbars.initialized`.

Проверка обновления окна исполняет настоящий effect `requestAnimationFrame`/`ResizeObserver`: изменение диапазона попадает в transition, после cleanup наблюдатель не запускает новые кадры. Проверки `CityWorld` также покрывают живой callback возврата мемоизированного редактора и отсутствие измерений скрытой строительной подсказки во время свайпа остальных вкладок.

Результаты нагрузочного сравнения с `07530b4` — `reports/city-sidebar-2026-10-25.json`: production React, локальный Chromium, CPU ×4, 36 городов ×144 здания, 64 записи очереди, ответы отпускаются во время правого pan. Максимальный интервал RAF очереди уменьшился с 500–583 до 183–184 мс, показателей — с 67–150 до 17 мс; повторных пересборок карты/подписей нет. Это синтетические наблюдения, не гарантия плавности на любом устройстве: в очереди остаются интервалы кадров, поэтому #180 остаётся открытой. Эксперимент с кэшем размеров Canvas не дал измеренного выигрыша и исключён.
