Размер ещё не начатых слоёв оценивается средним по известным. Не вышло (сокет, приватный реестр) — прежний `docker pull -q`. В режиме compose `docker compose pull` идёт после и лишь сверяет образ.
- `GET /api/build` отдаёт `update {state,message,progress}`, пока обновлятель занят; `useBuildWatcher` опрашивает раз в 1,5 с во время обновления и минуту после нажатия «Обновить» (`watchUpdate`).

- Прогресс появится, только когда на сервере обновится образ `:updater` (в compose: `docker compose pull updater && docker compose up -d updater`; в Portainer он подтягивается при передеплое стека).

### Ускорители: слоты одного типа освобождаются по одному
- `modules/boosterAutomation.js`: цикл очереди считает свободные слоты по реальным инстансам из игры (`GET /boosters/active`, один запрос на проход и только при непустой очереди; сбой — запасной расчёт по БД). Раньше он брал из БД максимальное время окончания типа и счётчик, который сам не уменьшается: у эпика при 4/4 ждал конца последнего инстанса. Теперь, если следующий в очереди тот же тип, что активен, он ставится, как только освобождается слот (эпик: осталось 18 ч на трёх → ещё один, снова 24 ч). Другой тип по-прежнему ждёт окончания всех инстансов текущего, лега — окончания своей. Проход заодно записывает в БД фактическое «Активно N/M» для вкладки.
- Вкладка «Ускорители»: число на кнопке «В очередь» — `CounterLabel` Primer вместо скобок.

### Docker-образ и обновления
- Бот — готовый образ `ghcr.io/corsairguy/toncity_bot`, собирается `.github/workflows/docker.yml` на каждую ветку (кроме `claude/**`) и тег `vX.Y`, под `linux/amd64` и `linux/arm64` (сервер — ARM). Теги: имя ветки (`main` ещё и `latest`), `X.Y` + `stable` для релиза, `sha-<коммит>`, `updater` для обновлятеля (только из `main`). `Dockerfile` двухстадийный: панель собирается один раз на платформе сборщика, `npm ci` по lock-файлам, `APP_COMMIT`/`APP_REF` в образе, справочники `config/` докладываются из образа, только если их нет (изменённый в git справочник на сервер сам не приедет), запуск `exec node` под `init: true`.
- `docker-compose.yml`: `bot` из образа (с хоста только `config/` и `logs/`) + сервис `updater`; `docker-compose.dev.yml` — режим разработки с кодом с хоста. На сервере один раз: `docker compose up -d --remove-orphans`, переменные `WATCHTOWER_*` из `.env` можно удалить.
- Обновлятель `updater/updater.sh` (версия 4) вместо Watchtower (тот не умеет менять тег): заявки и статус — файлы `config/updater/*.json`. В режиме compose пишет `BOT_TAG` в `.env` и пересоздаёт бота; пульс `heartbeat.json` пишется и во время заявки, поэтому панель не считает его мёртвым посреди обновления. Если обновлятель перезапустился посреди заявки, она закрывается ошибкой.
- Portainer: `docker-compose.portainer.yml` (данные от абсолютного `DATA_DIR`, переменные из Portainer через явный `environment`) и инструкция `docs/portainer.md`. Режим включается одним `PORTAINER_TOKEN`: обновлятель сам находит API Portainer (заданный `PORTAINER_URL`, https :9443, http :9000, http :9443 на `host.docker.internal`), правит `BOT_TAG` стека и передеплоит его с `pullImage`. Сначала сам скачивает образ (совпал с запущенным — «уже установлена» без Portainer), на 409 «deployment already in progress» повторяет до 5 минут, после PUT ждёт пересоздания бота до 5 минут.
- Бэкенд: `utils/selfUpdate.js` (заявки, история версий, `updaterInfo().busy` — заявка в работе моложе 20 минут, на это время новая не принимается), `POST /api/update {tag}` (не стартует посреди операций `opRegistry` без `force`), `utils/autoUpdate.js` (автообновление раз в 10 мин, `settings.update.auto`, по умолчанию включено, только плавающие каналы и только после сборки образа).
- Проверка версии `utils/versionCheck.js` + `GET /api/version`: ветки, релизы, голова канала, сборка образа в Actions. Проверяется сразу при запуске веб-сервера, кэш 30 минут (3 минуты, пока собирается образ; при ошибке 5 минут). Лимит GitHub без ключа 60 запросов/час бережётся условными запросами (ETag, ответы в `config/github-cache.json`, 304 в лимит не засчитывается); упёрлись в лимит — до сброса GitHub не трогаем. Необязательный `GITHUB_TOKEN` поднимает лимит до 5000/час. Кнопка ручной проверки (меню и Настройки → Обновления) идёт на GitHub всегда, кроме повторного клика в пределах 10 секунд; раньше в течение минуты после любой проверки (в том числе автоматической) она мгновенно отдавала старый ответ. Ответ из кэша помечен `cached`, панель пишет под кнопкой «Проверено только что» или «Проверено N с назад».
- `GET /api/build` — коммит, время старта процесса и занят ли обновлятель, без GitHub.

### Ускорители: очередь по порядку, «Обновить с игры» читает склад
- `modules/boosterAutomation.js`: цикл автоускорителей больше не перескакивает через позицию, которую сейчас нельзя активировать. Раньше при очереди «лега, эпик ×4» и активном эпике следующим включался эпик (тот же тип стакается), а лега ждала до конца всех эпиков. Теперь первая недоступная позиция останавливает проход: лега дожидается конца текущего эпика, активируется, и только после её окончания идут эпики. Пропускаются лишь позиции без запаса в инвентаре. После активации тип сразу считается активным, поэтому другой тип в том же проходе не включается.
- Так же очередь уже считал прогноз (`modules/progress.js loadBoosterTimeline`), теперь цикл с ним совпадает.
- Кнопка «Обновить с игры» на вкладке «Ускорители» (`POST /api/city-strategy/:account/boosters/check`) теперь сначала перечитывает склад аккаунта (`runInventory`, с пробросом ошибки), а потом сверяет активные. Ускорители, полученные после ежедневной синхронизации, сразу появляются в списке, израсходованные пропадают; в ответе `added` — сколько новых типов нашлось, панель пишет это во всплывашке.
